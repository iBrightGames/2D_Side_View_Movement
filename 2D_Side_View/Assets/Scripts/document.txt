## 🎯 Overview

### What is This?
A **modular, data-driven movement system** for Unity that allows you to create and configure any type of movement through ScriptableObjects without writing code. Perfect for rapid prototyping and multi-game development.

### Key Features
- ✅ **ScriptableObject-Based**: All movement configured via data files
- ✅ **Input Agnostic**: Supports player input, AI, and scripted events
- ✅ **Physics-Ready**: Full Rigidbody2D and Transform support
- ✅ **Execution Modes**: Continuous, Triggered, and Charged movements
- ✅ **Completion Tracking**: Time, rotation, distance-based completion
- ✅ **Reusable**: Design once, use across multiple games

### Use Cases
- 2D Platformers (jump, walk, dash)
- Top-down games (WASD movement, dodge rolls)
- Racing games (acceleration, boost)
- Fighting games (combos, special moves)
- Puzzle games (grid movement, rotation)

```
        ┌───────────┴───────────┐
        │                       │
        ▼                       ▼

                    │ (Static Utility) │

```

## 🚀 Quick Start Guide

### Step 1: Setup GameObject
1. Create a GameObject (e.g., "Player")
2. Add `MovementController` component
3. Add `InputMovementHandler` component
4. Add `Rigidbody2D` (if using physics movements)

### Step 2: Create Input ScriptableObject
**Right-click in Project → Create → Movement → Input**

**For Player Control:**
- Create `ExternalInputSO`
- Assign Input Action Reference (e.g., WASD, Space)

**For AI/Script Control:**
- Create `InternalInputSO`
- Toggle `IsActive` at runtime or call `Trigger()`

### Step 3: Create Movement ScriptableObject
**Right-click in Project → Create → Movement → Rigidbody or Transform**

Choose movement type:
- **Continuous**: For walking, running, flying
- **Triggered**: For jumping, dashing, attacking
- **Charged**: For charged attacks, power jumps

### Step 4: Connect via Bridge
In `InputMovementHandler`:
1. Set array size to 1+
2. Drag Input SO to `Base Input SO`
3. Drag Movement SO to `Movement SO`

### Step 5: Configure Movement
Set values in Movement SO:
- **Direction**: Vector3 (magnitude = strength)
- **Force Type**: Linear, Angular, or Scaler
- **Use Input Direction**: ✅ for player-controlled direction

**Done!** Press Play and test.

## 🎮 Movement Types

### 1️⃣ Continuous Movement
**Behavior**: Executes while input is held

**Best For**:
- Walking/Running
- Flying
- Swimming
- Aiming rotation

**Configuration**:
```
Direction: (5, 0, 0)        // Speed in units/sec
Force Type: Linear
Use Input Direction: ✅
Max Duration: 0 (unlimited)
```

**Example Use**: WASD character movement

---

### 2️⃣ Triggered Movement
**Behavior**: Executes once to completion

**Best For**:
- Jumping
- Dashing
- Spinning
- Combo attacks
- Teleporting

**Configuration**:
```
Direction: (0, 10, 0)       // Jump force
Force Type: Linear
Completion Type: Time
Completion Value: 0.5       // 0.5 seconds
Block Until Complete: ✅
```

**Completion Types**:
- **Time**: Completes after X seconds
- **Rotation**: Completes after X degrees rotated
- **Distance**: Completes after traveling X units
- **None**: Completes immediately (single impulse)

**Example Use**: Space bar jump that can't be interrupted

---

### 3️⃣ Charged Movement
**Behavior**: Hold to charge, release to execute

**Best For**:
- Charged jumps
- Power attacks
- Bow/slingshot mechanics
- Dash with variable distance

**Configuration**:
```
Direction: (15, 0, 0)       // Max force
Force Type: Linear
Min Charge Time: 0.2        // Minimum hold time
Max Charge Time: 2.0        // Full charge time
Charge Multiplier: 2.0      // 1x → 3x force range
```

**Example Use**: Hold Space to charge jump, release to launch

## 🎛️ Input Systems

### External Input (Player Control)

**Setup**:
1. Create Input Actions in Input System
2. Create `ExternalInputSO`
3. Assign Input Action Reference

**Supported Input Types**:
- **Button**: Triggers on press (Jump, Attack)
- **Value (Vector2)**: Continuous direction (WASD, Joystick)
- **Value (Float)**: Continuous value (Trigger, Mouse Scroll)

**Inspector Fields**:
```
Input Action: [Assign Input Action Reference]
```

**Features**:
- Automatic input direction extraction
- Works with keyboard, gamepad, touch
- Phase detection (Started, Performed, Canceled)

---

### Internal Input (AI/Script Control)

**Setup**:
1. Create `InternalInputSO`
2. Reference in your scripts
3. Control via code

**Control Methods**:

**Method 1: Continuous Bool**
```csharp
public InternalInputSO patrolInput;

void StartPatrolling()
{
    patrolInput.IsActive = true;
}

void StopPatrolling()
{
    patrolInput.IsActive = false;
}
```

**Method 2: One-Shot Trigger**
```csharp
public InternalInputSO jumpInput;

void PerformJump()
{
    jumpInput.Trigger();  // Executes once, auto-resets
}
```

**Method 3: Direct Field Access**
```csharp
public InternalInputSO attackInput;

void Update()
{
    if (playerInRange)
    {
        attackInput.TriggerOnce = true;  // Manual control
    }
}
```

**Inspector Fields**:
```
Is Active: ☐              // Toggle for continuous execution
Trigger Once: ☐           // One-shot trigger (auto-resets)
```

## 🎨 Configuration Examples

### Example 1: Top-Down Character (WASD Movement)

**Input Setup**:
- Input Actions: WASD → Vector2
- Create `ExternalInputSO_WASD`
- Assign WASD action

**Movement Setup**:
- Create `ContinuousRigidbodyMovement_Walk`
- Direction: `(5, 0, 0)` (5 units/sec speed)
- Force Type: `Linear`
- Force Mode: `Force`
- **Use Input Direction: ✅ TRUE**
- Max Duration: `0` (unlimited)

**Bridge Configuration**:
```
Base Input SO: ExternalInputSO_WASD
Movement SO: ContinuousRigidbodyMovement_Walk
```

**Result**: Player moves in WASD direction at 5 units/sec

---

### Example 2: Platformer Jump (Space Key)

**Input Setup**:
- Input Actions: Space → Button
- Create `ExternalInputSO_Jump`
- Assign Space action

**Movement Setup**:
- Create `TriggeredRigidbodyMovement_Jump`

- Force Mode: `Impulse`
- **Use Input Direction: ❌ FALSE**

**Result**: Press Space for consistent jump, can't double-jump until landing

### Example 6: AI Patrol Behavior

**Input Setup**:
- Create `InternalInputSO_Patrol`
- No Input Actions needed

**Movement Setup**:
- Create `ContinuousTransformMovement_Patrol`
- Direction: `(2, 0, 0)` (patrol speed)
- Force Type: `Linear`
- **Use Input Direction: ❌ FALSE**
- Max Duration: `0` (unlimited)

**AI Script**:
```csharp
public class EnemyAI : MonoBehaviour
{
    public InternalInputSO patrolInput;
    private bool movingRight = true;

    void Update()
    {
        if (ReachedWaypoint())
        {
            FlipDirection();
        }
    }

    void FlipDirection()
    {
        movingRight = !movingRight;
        // Flip the movement direction by toggling active
        patrolInput.IsActive = movingRight;
    }
}
```

**Result**: AI patrols back and forth automatically

## 🔧 Advanced Usage

### Multiple Movements per Character

You can assign multiple bridges for complex behavior:

```
Bridge 0: WASD + Walk Movement
Bridge 1: Space + Jump Movement
Bridge 2: Shift + Dash Movement
Bridge 3: E + Spin Attack
Bridge 4: AI Bool + Idle Animation
```

**Tips**:
- Use `blockUntilComplete` to prevent overlapping triggered moves
- Continuous movements can run simultaneously
- Charged movements automatically block while charging

---

### Dynamic Movement Switching

```csharp
public class MovementSwitcher : MonoBehaviour
{
    public InternalInputSO walkInput;
    public InternalInputSO runInput;

    public void SetWalking()
    {
        walkInput.IsActive = true;
        runInput.IsActive = false;
    }

    public void SetRunning()
    {
        walkInput.IsActive = false;
        runInput.IsActive = true;
    }
}
```

---

### Event-Driven Gameplay

```csharp
public class GameplayController : MonoBehaviour
{
    private MovementController movementController;

    void Start()
    {
        movementController = GetComponent<MovementController>();
        
        // Subscribe to events
        movementController.OnMovementStarted.AddListener(OnMoveStart);
        movementController.OnMovementCompleted.AddListener(OnMoveComplete);
    }

    void OnMoveStart()
    {
        Debug.Log("Movement started!");
        // Play sound, start animation, etc.
    }

    void OnMoveComplete()
    {
        Debug.Log("Movement completed!");
        // Award points, trigger next action, etc.
    }
}
```

---

### Custom Conditions (Future Extension)


## 📚 API Reference

### BaseInputSO (Abstract)
**Methods**:
- `bool ShouldExecute()` - Returns true when movement should trigger
- `bool IsHeld()` - Returns true while input is held

---

### ExternalInputSO : BaseInputSO
**Fields**:
- `InputActionReference inputAction` - Unity Input System action

**Methods**:
- `Vector3 GetInputDirection()` - Returns input direction vector

---

### InternalInputSO : BaseInputSO
**Fields**:
- `bool IsActive` - Continuous execution toggle
- `bool TriggerOnce` - One-shot trigger (auto-resets)

**Methods**:
- `void Trigger()` - Helper to set TriggerOnce
- `void Activate()` - Helper to enable IsActive
- `void Deactivate()` - Helper to disable IsActive

---

### MovementForceSO (Abstract)
**Properties**:
- `ForceType ForceType { get; }` - Linear, Angular, or Scaler
- `Vector3 Direction { get; }` - Movement direction/magnitude
- `bool UseInputDirection { get; }` - Use input vs fixed direction
- `MovementExecutionType ExecutionType { get; }` - Continuous, Triggered, or Charged

---

### ContinuousRigidbodyMovement : MovementForceSO
**Fields**:
- `ForceMode2D forceMode2D` - Force, Impulse, etc.
- `float maxDuration` - Max execution time (0 = unlimited)

---

### TriggeredRigidbodyMovement : MovementForceSO
**Fields**:
- `ForceMode2D forceMode2D` - Force application mode
- `CompletionType completionType` - Time, Rotation, Distance, Condition, None
- `float completionValue` - Value for completion (seconds, degrees, units)
- `bool blockUntilComplete` - Prevent re-triggering

---

### ChargedRigidbodyMovement : MovementForceSO
**Fields**:
- `ForceMode2D forceMode2D` - Force application mode
- `float minChargeTime` - Minimum hold duration
- `float maxChargeTime` - Maximum charge duration
- `float chargeMultiplier` - Force scaling (1x + multiplier)

---

### MovementController : MonoBehaviour
**Fields**:
- `Rigidbody2D _rigidbody2D` - Physics body reference
- `Transform _transform` - Transform reference
- `UnityEvent OnMovementStarted` - Fires when movement begins
- `UnityEvent OnMovementCompleted` - Fires when movement completes

**Methods**:
- `void ApplyForce(MovementForceSO force, Vector3 inputDirection = default)` - Apply movement force
- `Coroutine StartTriggeredMovement(TriggeredRigidbodyMovement, Vector3)` - Start triggered physics movement
- `Coroutine StartTriggeredMovement(TriggeredTransformMovement, Vector3)` - Start triggered transform movement

---

### InputMovementHandler : MonoBehaviour
**Fields**:
- `InputMovementBridge[] inputMovementBridges` - Array of input-movement pairs

**Internal**:
- Automatically processes all bridges in Update()
- Manages execution state for all movement types
- Tracks active coroutines and timers

## ✅ Best Practices

### Performance
1. **Limit Bridge Count**: Keep under 10 bridges per handler for optimal performance
2. **Use Rigidbody for Physics**: Always use Rigidbody movements when collision detection needed
3. **Pool Movement SOs**: Reuse ScriptableObjects across multiple GameObjects

### Design
1. **Separation of Concerns**: One movement per action (separate Walk and Run)
2. **Meaningful Names**: Use descriptive SO names (Jump_HighPower vs Movement_03)
3. **Force Magnitude**: Use Direction vector magnitude as strength (length = speed/force)

### Input
1. **External for Player**: Always use ExternalInputSO for player control
2. **Internal for AI**: Use InternalInputSO for non-player entities
3. **Direction Consistency**: Enable UseInputDirection for movement, disable for fixed actions

### Debugging
1. **Test Incrementally**: Add one bridge at a time
2. **Monitor Events**: Use OnMovementStarted/Completed for debugging
3. **Check References**: Ensure Rigidbody2D exists for Rigidbody movements

## 🐛 Troubleshooting

### Movement Not Working
**Check**:
- ✅ InputMovementHandler and MovementController on same GameObject
- ✅ Input Action enabled in Input System
- ✅ Bridge references assigned (not null)
- ✅ Rigidbody2D exists if using Rigidbody movements

### Wrong Direction
**Check**:
- ✅ UseInputDirection toggle matches intent
- ✅ Direction vector magnitude (not just direction)
- ✅ Input Action type (Vector2 for directional, Button for trigger)

### Movement Continues Forever
**For Continuous**: Expected behavior (use maxDuration to limit)
**For Triggered**: Check completionType and completionValue settings

### Can't Trigger Again
**Check**:
- ✅ blockUntilComplete is enabled
- ✅ Movement completion conditions met
- ✅ No conflicting continuous movement blocking

### Charged Movement Not Releasing
**Check**:
- ✅ Input Action type is Button (not Value)
- ✅ minChargeTime isn't too high
- ✅ Input properly releasing (check Input System debugger)

### Physics Feels Wrong
**Check**:
- ✅ ForceMode2D setting (Force vs Impulse)
- ✅ Rigidbody2D mass and drag settings
- ✅ Direction magnitude (force strength)
